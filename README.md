# Milkshake Studio

Next.js App Router + React + TypeScript + Tailwind CSS. Две дизайн-системы: светлая Milkshake Pop и тёмная Milkshake After Dark. Переключатель в шапке меняет композицию и оформление без перезагрузки; выбор сохраняется в localStorage. Форма, цены и контент общие.

Статический первый эскиз и предыдущие стили сохранены в `design-pop/`. Рабочее приложение находится в `src/`. Цены — только в `src/config/pricing.ts`, тексты процесса и FAQ — в `src/config/content.ts`. Первый экран вынесен в `src/components/studio-hero.tsx`. Актуальные стили: `src/styles/base.css`, `pop.css` и `dark.css`.

Pop переработан по принципам светлой редакционной композиции bfd.su; Dark — по принципам полноэкранной подачи zbca.ru. Чужие изображения, логотипы и коммерческие утверждения не используются. Оригинальная графика и промпты описаны в `public/images/ART-DIRECTION.md`. На мобильных подгружаются уменьшенные WebP, а не тяжёлая 3D-сцена.

## Локально

Нужны Node.js 24 и pnpm. Установите зависимости `pnpm install --frozen-lockfile`, скопируйте `.env.example` в `.env`, затем `pnpm dev`. Откройте http://127.0.0.1:3000.

В PowerShell можно запускать уже установленный проект командой `npm.cmd run dev`: расширение `.cmd` помогает, когда PowerShell блокирует `npm.ps1`. Если сервер этого проекта уже запущен, откройте указанный адрес вместо запуска второго экземпляра. Зависимости рекомендуется устанавливать через pnpm, чтобы использовать существующий lock-файл.

Понятное объяснение разделов, файлов и пути заявки: [STRUCTURE.md](STRUCTURE.md).

Без внешних ключей интерфейс работает, форма явно сообщает о недоступности отправки. Введённые поля не отправляются. Не показываем личные контакты владельца. Используется Webpack: в текущей Windows-среде Turbopack завершался ошибкой дочернего процесса PostCSS.

Проверки: `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`. Production: `pnpm start`. Standalone-контейнер использует `node server.js`. TypeScript 6 и ESLint 9 закреплены для совместимости текущих плагинов Next.js: TypeScript 7 и ESLint 10 пока не поддерживаются всей цепочкой линтинга.

## Telegram и CAPTCHA

Создание бота и подключение группы: [отдельная инструкция](TELEGRAM-SETUP.md).

Создайте Managed-виджет в Cloudflare Turnstile, добавьте реальные hostnames сайта. В `.env` укажите `NEXT_PUBLIC_TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY`, `TURNSTILE_HOSTNAMES` (через запятую без протокола), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и `REDIS_URL`. Скрипт CAPTCHA загружается только при включённой форме. Сайт передаёт серверную настройку виджета в React, поэтому в этом проекте ключ также можно передавать контейнеру во время запуска.

Сервер проверяет CAPTCHA, hostname и action `lead` до Telegram. Тестовые ключи в production блокируются. Для ручных локальных тестов можно использовать официальные ключи https://developers.cloudflare.com/turnstile/troubleshooting/testing/ при `pnpm dev` и соответствующем разрешённом hostname из результата тестовой проверки. Успешный внешний сценарий без реальных ключей не подтверждён.

`POST /api/leads`: JSON до 16 КБ, Zod-валидация, согласие, honeypot, проверка Origin, глобальное ограничение 100 запросов/минуту, при доверенном proxy также 5 попыток на IP/10 минут. Proxy обязан заменять X-Forwarded-For, иначе `TRUST_PROXY` оставьте false. Для публичного сервера включите доверенный proxy, настройте body/read timeouts на его уровне и не открывайте порт приложения наружу. При недоступном Redis запросы отклоняются. Redis хранит хеши, счётчики и статусы, а не содержимое заявок.

После подтверждения Telegram сохраняется статус отправки на 24 часа. При тайм-ауте невозможно достоверно определить, дошло ли сообщение: статус pending тоже хранится 24 часа, повтор с тем же ID блокируется. Проверяйте группу до повторной заявки. Данные остаются в форме. Абсолютная гарантия exactly-once у Telegram Bot API отсутствует.

## Перед публичным запуском

`PRIVACY_READY=false` отключает сбор заявок независимо от ключей. `/privacy` — честная страница подготовки, а не готовая юридическая политика. Уточните юрисдикцию, реального оператора, контакт для обращений, сроки хранения, порядок отзыва/удаления, требования к локализации, трансграничной передаче и согласиям для Telegram и Cloudflare. После проверки замените страницу реальной политикой и текстом согласия, затем включайте флаг. Отсутствие оформления бизнеса не отменяет вопросы обработки данных.

Индексация сейчас запрещена: согласование дизайна. После выбора домена и завершения сайта добавьте canonical, Open Graph, sitemap и production robots. Необязательная аналитика не подключена. Шрифт Golos Text пока загружается из Google Fonts; до публичного запуска рекомендуется перенести разрешённые файлы шрифта локально, чтобы исключить внешние запросы.

## Docker и VPS

После заполнения `.env`: `docker compose up -d --build`. Приложение доступно на http://127.0.0.1:3000. Redis не публикует порт, его AOF хранится в именованном томе. В образ не попадает `.env`, процесс приложения непривилегированный.

Docker в текущей среде не установлен; сборка контейнера пока не проверена. Для VPS установите Docker Engine/Compose, выберите домен и направьте DNS A-запись на сервер. Пример `Caddyfile.example` рассчитан на Caddy на хосте. Замените домен, установите Caddy, откройте 80/443, задайте `SITE_URL=https://ваш-домен`, `TURNSTILE_HOSTNAMES=ваш-домен`, включите `TRUST_PROXY=true` за Caddy. HTTPS выпускается Caddy автоматически после корректной настройки DNS и портов.

Обновление: получить код, выполнить `docker compose up -d --build`. Логи: `docker compose logs --tail=100 web`; не публикуйте секреты. Сохраняйте резервную копию `.env`, Caddyfile и Redis-тома в закрытом хранилище; `.env` никогда не коммитьте. Healthcheck `/api/health` проверяет доступность приложения, а не доставку в Telegram.
