# Milkshake Studio

Next.js + React + TypeScript. Две темы с общим содержанием, ценами и формой. Приложение находится в `src/`, стили — в `src/styles/`, цены — в `src/config/pricing.ts`.

## Локальный запуск

Рекомендуется Node.js 24 и pnpm. Установите зависимости `pnpm install --frozen-lockfile` и запустите `pnpm dev`. В Windows можно выполнить `npm.cmd run dev`. Адрес: http://127.0.0.1:3000.

## Приём заявок

По запросу владельца форма отправляет заявки напрямую в Telegram без обязательных Turnstile и Redis. Форма и сервер проверяют поля и согласие, сервер проверяет Origin, размер JSON и скрытое поле. Ограничения частоты и надёжного исключения повторной доставки теперь нет: при ошибке доставки заявка могла попасть в чат, повтор может создать дубль.

В `.env` укажите `SITE_URL=https://milk.termitsdigital.ru`, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Флаг `PRIVACY_READY` должен оставаться `false` до завершения проверки политики, текста согласия и организации обработки данных. Инструкция по боту: [TELEGRAM-SETUP.md](TELEGRAM-SETUP.md). Никакие секреты в Git не добавляются.

## Публикация

Сайт развёрнут на `milk.termitsdigital.ru` в Dokploy. Домен, HTTPS и переменные окружения настроены. Источник приложения — публичный репозиторий `https://github.com/Milk-Paradise/site.git`, ветка `main`. После отправки изменений в GitHub запустите Deploy в Dokploy; автоматический webhook отдельно не настроен. Dockerfile публикует приложение на порту 3000. Публичная доставка заявок пока не проверена и форма отключена. Индексация пока запрещена; после завершения проекта настройте robots, canonical, sitemap и Open Graph.

Политика на `/privacy` пока черновик. Подробности: [LAUNCH-READINESS.md](LAUNCH-READINESS.md). Команды проверок: `npm.cmd run typecheck`, `npm.cmd run lint`, `npm.cmd test`, `npm.cmd run build`.

## Журнал заявок

Каждая проверенная заявка после согласия сохраняется строкой JSON в UTF-8 `leads.txt` в корне проекта до попытки отправки в Telegram. Если запись не удалась, форма сообщает об ошибке; если Telegram недоступен, запись остаётся в журнале. Повторы могут создать несколько строк. Файл не находится в `public/`, исключён из Git и Docker build context и может содержать персональные данные — ограничьте доступ к серверу и резервным копиям. Автоматическое удаление по сроку не настроено.

Откройте `/leads-log`. Браузер запросит имя пользователя `admin` и пароль из `LEAD_LOG_PASSWORD`. Для локального теста пароль задан в `.env`; при `NODE_ENV=production` пароль короче 12 символов не допускается. Перед публикацией задайте новый уникальный длинный пароль и HTTPS. Базовая авторизация не заменяет ограничение доступа и защиту от перебора на уровне сервера. Журнал отображается без кэширования. Изменения переменных окружения требуют перезапуска сервера.

В Docker файл хранится в `/data/leads.txt`, а compose подключает том `lead-data` к `/data`. Для Dokploy необходимо отдельно настроить постоянный том в `/data` с правом записи пользователем приложения (UID 1001); без тома данные при пересоздании контейнера могут исчезнуть. Не публикуйте `/data` как статические файлы. Настройте резервное копирование тома и удаление по согласованному сроку. Убедитесь, что журналы и резервные копии соответствуют актуальной политике обработки данных до включения формы.
